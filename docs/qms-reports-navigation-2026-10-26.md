# QMS Reports and navigation

QMS dropdowns now have two levels: category, then a direct workspace link. Module views are not nested accordion destinations. The drawer uses the same module-level destinations. Settings notifications are reached through Settings, removing the duplicate Mail Identity menu item. Shared register workspaces and provider lists expose their supported views as page tabs. Existing audit, CAR and Settings workflows retain their own navigation; the persistent QMS link returns to the top level.

Reports has a dedicated route owner ahead of the generic-register shortcut. It provides executive summary, audit performance, CAR performance, finding trends and training record validity, plus a download catalogue. The outer shortcut does not supply nested route parameters, so the owner derives the tenant from the validated route classification when needed. Detailed CAR analysis remains accessible from its report and has an explicit return action.

Report previews and downloads read tenant-filtered operational sources. Period defaults and generation times come from server UTC. Each report states its date cohort and population. Deleted audits and their findings are excluded. Training includes active records completed in the period, with separate verification and validity information; it is not presented as a full role-requirement compliance certification. Finding reports include monthly counts. Executive summaries sum record counts rather than counting grouped rows. Preview timestamps display the viewer's timezone explicitly.

Preview tables paginate 25 rows locally. CSV and standalone printable HTML retrieve the complete selected report from the server, including metadata and summary counts. Printable HTML can be opened in a browser and printed or saved as PDF; no server-generated PDF is claimed. Downloads retrieve a fresh population and may differ from an older preview. Output requires `qms.reports.export`; viewing requires `qms.reports.view`. CSV formula-like values are neutralized and HTML values escaped. Reports refuse more than 10,000 detail rows or periods longer than five years instead of silently generating partial outputs. Preview reads bypass persisted/offline API caching.

Controlled Documents and AeroDoc are removed from QMS navigation. Their old workspace URLs hand off to the existing native DMS library, changes, distribution or compliance pages. Supported document-revision reader links remain compatible with existing evidence references. No document records or files are deleted. The legacy tenant `qms_documents` register was empty during the live review, so no source-record migration was needed for this UI ownership change.

Verification artifacts are kept under ignored `.artifacts`. Six backend tests cover tenant/date filtering, deleted audits, source data, executive totals, row limits, output escaping and distinct view/export authorization. Thirty-one app/navigation unit checks passed; additional route-loader and registry checks validate report ownership. Browser checks cover direct menu destinations, page views, Settings/provider regressions, read-only reports, downloads, mobile layout and DMS aliases. The initial report browser failure exposed the missing outer-route tenant parameter; all four report scenarios passed after correction. The broader suite passed the other 16 scenarios, including 33 shared-register views. These role and register checks use isolated fixtures; live checks use the supplied staff administrator.

Final live checks used the public Tailscale portal and deployed production assets. All five report endpoints returned 200: 2 audits, 3 CARs, 4 findings and 466 active training records, with the executive grouped summary. The audit CSV downloaded completely, and its standalone HTML was opened and visually checked with both rows. The training CSV contained all 466 records (50,488 bytes), while its preview displayed 25 per page. Executive summary chips were checked against grouped record totals after correcting a group-count error. Mobile menus contain direct workspace links with no nested details/summary controls. The selected page tab now scrolls into view on direct entry and viewport resize. All five final report browser scenarios passed; the additional route unit suite passed 38 checks. The native DMS handoff displayed the existing two manuals and checklist under Document Control. A stray literal newline marker in its toolbar was removed. No audit, CAR, training or document record was changed for this report review.

Report narrative cells override the portal's generic single-line table truncation. Finding descriptions have a wider column and wrap their complete text; report downloads already contained the full source value. The browser regression includes a long narrative and checks that its cell does not clip the text. Final TypeScript checks produced no errors. Changed-source lint has no errors; three existing hook-dependency warnings remain in the legacy module workspace.
