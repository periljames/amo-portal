# Phase 5 — controlled provider documents, agreements and DMS/QMS integration

**Repository:** `periljames/amo-portal`. **Branch:** `codex/external-provider-platform-20261009`. **Single PR:** #560. **Status:** revised full-stack source committed; **not runtime accepted**. All migrations, testing, typecheck, build, lint, CI verification and browser/storage acceptance remain deferred until Phase 10 as instructed. No Phase 6 features have started.

## Canonical boundaries

- **DMS** owns published forms, published revision lifecycle, recorded document evidence assets, retention, legal holds and disposition; only its appointed control roles can govern retention. Provider cookies cannot access its staff endpoints.
- **QMS** owns provider Qualification/Quality decisions and canonical `quality_external_provider_evidence` VERIFIED status. Accepting a submission creates only a PENDING QMS evidence record; successful Quality verification is independent.
- **Procurement/Finance** own their commercial transaction records and the canonical supplier master. Maintenance agreements are extended in the existing QMS `quality_external_provider_contracts` rather than a second contracting registry; contract ACTIVE is not provider Quality approval or authorization to perform work.
- Existing external authenticated identities, grants, anti-CSRF, provider assignment scopes, Quality and Document Control authorizations remain in force.

## Source implementation

1. **Tenant/category requirements and record types.** `extprov_261015_docs` adds tenant-controlled classification, required/optional, expiry dates and advance-warning days, opt-in read-and-understood form acknowledgement, current published DMS exact-revision references, and a tenant-provided retention policy reference. The internal screen exposes all 23 requested classes as presets, not mandatory for every client. Policy revision and disabled classes are enforced server-side.
2. **Original upload/intake.** Secure provider `/documents` endpoints provide authorized current-form download, scoped requirements, forms acknowledgement, classified response upload, original download, history and partner-scoped audit assignment choices. For files up to **20 MiB**, the direct path streams and scans. For larger files up to **512 MiB**, the resumable path uses manifest-backed **8 MiB** object-store chunks, member/provider/tenant scope, bounded retry identities, per-part SHA-256, incomplete-part recovery, interruption/cancel/progress UI, ordered reassembly, whole-object SHA-256, file-format validation and configured fail-closed ClamAV streaming scan **before** recording the original. No transformative document conversion or internal repository is introduced.
3. **Retention bridge.** An appointed Document Control Officer uses `/maintenance/{amoCode}/doc-control/provider-evidence` (linked from the existing Document Control workspace) to register the reviewed original as an actual canonical `document_evidence_assets` entry of category `EXTERNAL_SOURCE`, with a `document_retention_dispositions` entry, explicit retention class, optional retention-until date, provenance, original hash and canonical DMS audit record. The same original remains in provider staging. The staff queue shows the linked DMS record and its live legal-hold/status. The existing DMS hold/disposition approvals remain authoritative. **QMS verification of staged evidence rejects items not registered in DMS or already disposed.**
4. **Review decisions.** Appointed Quality staff alone decide classified submissions as `ACCEPTED`, `RETURNED` or `REJECTED` with reason. Accepted intake creates only canonical QMS `PENDING` evidence. Existing QMS evidence endpoint performs independent Quality verification. Replacement is linked by composite tenant+provider FK; previous verified QMS status and staging state become SUPERSEDED **only when the new evidence is independently verified**. Originals and append-only event records are retained. Internal staff queue shows complete event history and original downloads.
5. **Controlled forms and acknowledgements.** Exact published forms are limited to explicit member document grants. When configured, a member must explicitly attest to reading/understanding the identified current revision before a document can be submitted. Acknowledgements are immutable, keyed to tenant/provider/member/requirement/exact DMS revision and have provider-scoped FORCE RLS. A new published revision requires a new acknowledgement.
6. **Read-only document viewing.** Partner original files open in an in-browser PDF/image/text view or the existing sandboxed DMS Word-layout renderer, with a separate original-file download. An opened document has not thereby been approved. Both DMS and external authorization continue to apply.
7. **Agreements.** The existing agreement model records counterparties, approved sites, Authority evidence reference, effective/expiry dates, renewal terms, termination notice, immutable executed revision links, and matched accepted signed originals. A valid active contract requires current PUBLISHED DMS source, matching original SHA, accepted staging evidence, independent QMS VERIFIED evidence, non-disposed canonical DMS evidence asset and retention registration, and date validity. Procurement mandatory-contract checks do not accept a purchase-order override to bypass this agreement. Amendment/renewal drafts carry tenant/provider-qualified predecessor and reason, with no premature supersession. Termination records `terminated_at`. Explicitly granted historical originals remain available read-only after termination or supersession without reviving work privileges.
8. **Reminders and cleanup.** The existing scheduled Quality worker produces deduplicated Quality Manager notices for policy-configured evidence expiry and per-contract notice windows. The same worker removes expired/complete temporary upload fragments while retaining completed original records. The worker executes tenant-scoped with an authorized provider RLS marker. No new scheduler, audit, CAR or procurement approval engine is added.

## Remaining deployment/Phase 10 acceptance requirements

- **Malware scanner**: configure `PROVIDER_DOCUMENT_CLAMD_HOST`, `PROVIDER_DOCUMENT_CLAMD_PORT` (default 3310) and `PROVIDER_DOCUMENT_CLAMD_SCAN_TIMEOUT_SECONDS` (30–900 seconds, default 240). Configure the **ClamAV server** to allow at least 512 MiB `INSTREAM` (`StreamMaxLength`, `MaxFileSize` and `MaxScanSize` must be selected for expected file types) and keep the scanner on a private authenticated/trusted service network. If missing or unreachable intake deliberately returns an error; provision and acceptance tests remain outstanding.
- **Storage**: object storage for staging and upload parts must be durable across app instances. Canonical DMS evidence storage currently follows existing `DOCUMENT_EVIDENCE_DIR`; for high availability, mount it on appropriately secure durable/shared storage and confirm checksum-preserving failover. The provider file hash and source metadata must survive migration or outage.
- **Governance**: `retention_policy_ref` names a tenant-selected policy but does not by itself create or validate a statutory retention period. A Document Control Officer must select and register the approved DMS retention class and retention-until date under actual tenant policy. This does **not** infer aviation Authority acceptance or cryptographically validate signatures; appointed personnel must perform those documented decisions.
- **No execution claim**: none of the modified code has been migrated, typechecked, linted, built, exercised through actual browser/storage/scanner/QMS/DMS processes, or manually sent through CI in this phase. The migration also includes a downgrade for controlled records; downgrade of a database containing larger-than-20-MiB or newer-status submissions requires an explicit data retention/migration decision rather than deletion.
- Full verification matrix and regressions remain in `PHASE10_VERIFICATION_LEDGER.md`. Keep PR #560 **open, unmerged** until Phase 10 and explicitly accepted live controls.
